# 毛选生存系统｜DIN 字体统一 + 专家级金句解读 + 上下篇进度关联 + 第一卷知识图谱（集成版）设计

## 背景与目标

当前系统已具备：

- 阅读库与章节页渲染（App Router）
- 章节页 TOC 折叠
- “书卷样式”排版
- 内容文件（第一卷 18 篇）已补齐：写作时间线/事件、金句与摘录、核心思想、来源链接

本设计将新增 4 类能力，并要求它们彼此可互相引用、可被程序解析，最终形成“第一卷知识图谱”作为首页入口。

目标：

1) **字体统一**：所有 ASCII 英文与数字（含常见英文标点）使用 DIN；中文仍使用宋体体系。
2) **专家级金句解读**：每篇“金句与摘录”升级为逐条深解（每条一段），必要时引用原文或本卷其它章节，体现“进度与互证”。
3) **上下篇进度关联**：每篇文章关联上一篇/下一篇（按写作时间先后顺序；日期精度到月时采用排序占位规则并提示）。
4) **第一卷知识图谱（集成到站点）**：新增 `/map` 页面（首页入口），并要求“每篇都要纳入图谱”；图谱节点包含文章+主题+概念+事件，布局支持三种可切换形态。

## 字体设计（DIN 覆盖 ASCII）

### 目标

- 英文与数字：DIN
- 中文：宋体
- 同一行中中英混排时，英文/数字自动使用 DIN，不需要手工包裹标签

### 实现策略

- 继续使用现有 `@font-face + unicode-range` 做字形覆盖
- 新增一个 DIN 字体族（例如 `WXAscii`）专门覆盖 ASCII 区间：
  - `unicode-range: U+0020-007E`
- 全站字体栈顺序：
  - `WXAscii`（ASCII）→ `WXSerif`（中文）→ 系统 fallback

### 验收

- 首页、阅读库、章节页、图谱页中任意出现的 ASCII 字母/数字统一为 DIN。

## 内容结构升级：专家级“金句与摘录”

### 目标

将“摘录”从引用列表升级为“专家级解读模块”，实现：

- 对“进度”的解释：该摘录在第一卷整体推进链条中处于哪一环
- 对“互证”的解释：必要时引用原文或其它章节（同卷优先）形成证据链

### 标准结构（每条）

每条摘录统一结构：

1. **摘录原句**（短句；必要时可加极短的上下文，不贴长段）
2. **深度解读段**（120–200 字）包含：
   - 语义拆解：判断/命令/边界/风险点
   - 进度定位：此句对应“从何处推进到何处”（例如：从阶级识别推进到联盟策略）
   - 互文证据：引用其它篇章的相关句/相关观点（注明标题与 slug）

### 互文引用的可解析约定

为便于图谱自动生成“互文边”，新增一个约定：

- 在解读段末尾添加一行：
  - `互文：v1-00x, v1-01y`（slug 列表）

渲染层面可保持为普通文本；解析层面由脚本提取并生成边。

### 验收

- 每篇至少 8 条摘录，每条都有 120–200 字解读段。
- 至少 3 条/篇含互文引用（同卷优先）。

## 上下篇进度关联（prev/next）

### 排序规则

以 `frontmatter.date` 排序：

- `YYYY-MM-DD`：直接作为排序键
- `YYYY-MM`：排序时使用 `YYYY-MM-01` 作为内部键，并在 UI 明示“通行版本仅标到月份”

同日冲突时：

- 以现有目录顺序（固定数组）作为稳定 tie-breaker

### 页面呈现

章节页新增“进度关联”区块：

- 上一篇：标题 + 一段“进度关系”说明（为什么它是上一环）
- 下一篇：标题 + 一段“进度关系”说明（为什么它是下一环）

### 验收

- 第一卷 18 篇均能正确产生 prev/next（首篇无 prev，末篇无 next）。
- 章节页能稳定显示并可跳转。

## 第一卷知识图谱（/map）

### 用户入口

- 首页新增入口按钮：`知识图谱`
- `/map` 页为主要入口；后续可在章节页补充快捷入口，但非必需

### 数据模型（节点/边）

节点类型（可筛选开关）：

- **文章**：每篇 1 节点（18 个）
- **主题**：来自 `frontmatter.tags`
- **概念**：来自 `frontmatter.concepts`（需补齐）
- **事件**：来自“历史坐标 → 时间线（事件）”条目（按日期+标题去重聚合）

边类型：

- `progress`：上一篇 → 下一篇（时间序）
- `has_tag`：文章 → 主题
- `has_concept`：文章 → 概念
- `mentions_event`：文章 → 事件
- `cross_ref`：文章 → 文章（来自“互文：slug 列表”）

### 交互与布局

通用交互：

- 搜索：按节点名称搜索，聚焦并高亮邻接节点
- 筛选：按节点类型开关、按核心等级（S/A/B）、按时间范围（事件/文章）
- 点击文章节点：跳转 `/library/[slug]`
- 点击概念/主题/事件：过滤+高亮相关文章列表
- 缩放/拖拽：画布缩放和平移；节点可拖拽
- LocalStorage 记忆：布局、筛选条件、最后一次聚焦节点

布局切换：

1. **力导向聚类**（默认）：d3-force + 碰撞/中心力，按节点类型与核心等级做初始聚类。
2. **时间轴骨架**：文章按时间排布成横轴，事件节点附着到最近文章/时间点，跨篇互文边用弧线显示。
3. **分层同心**：内核（方法论/战略）概念在内圈，组织/经济/群众等在中圈，文章与事件在外圈。

### 依赖与实现选择

新增依赖（需要在实现阶段确认版本并落盘）：

- `d3-force`（力导向）
- 可选：`d3-quadtree`（更稳定的碰撞/邻近查询）、`d3-zoom`（缩放平移）

为降低 bundle：

- 仅在 `/map` 页动态导入相关模块（客户端组件内按需加载）

### 验收

- `/map` 在本地 dev 可访问，不出现 Not Found
- 三种布局可切换并可用（至少：初版切换后节点可见、可搜索、可点击跳转）
- 18 篇文章全部出现在图谱中，并能从图谱跳回章节页

## 内容规范扩展：frontmatter.concepts

### 字段定义

在 `ChapterFrontmatter` 新增：

- `concepts: string[]`（必填，建议 6–12 个/篇）

概念词表原则：

- 词形稳定（避免同义词泛滥）
- 优先来自第一卷核心方法学（阶级分析/群众路线/调查研究/统一战线/组织纪律/战略节奏等）

### 验收

- 校验脚本更新后：18 篇全部包含 concepts 且为数组
- `/map` 能基于 concepts 聚类与过滤

## 风险与对策

- 图谱节点过多导致拥挤：默认按类型/等级过滤（文章+概念优先），事件节点默认折叠，用户可开启。
- 概念词表漂移：设定“概念词表文件”（可选）作为 canonical 列表，新增概念需复用或映射。
- 引用过长：解读段限制 120–200 字，引用句保持短句，不贴大段原文。
