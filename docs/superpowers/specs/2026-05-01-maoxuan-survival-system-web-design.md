# 毛选生存系统 Web 版（Next.js）设计稿

## 1. 背景与目标

目标是把《毛选》的“方法论内核”做成一个可用、可训练、可扩展的 Web 系统（V1），满足：

- 阅读库：两论双核优先，后续章节可持续加入
- 生存工具箱：输入处境→调用模型→输出行动步骤/校验/止损
- 训练与复盘：题库+场景推演+模板填写，本地保存（LocalStorage）
- 双入口组织：按卷/篇 + 按主题/标签聚合

约束：

- 基于现有 Next.js 14（App Router）项目继续开发，不做“从零搭建新仓库”
- 先本地保存，未来可升级数据库与登录

非目标（V1 不做）：

- 登录体系、云端多端同步
- 全量全文搜索的复杂索引（可保留扩展点）
- 多人协作编辑内容

## 2. 用户与核心场景

用户类型：

- 学习者：按篇阅读、做训练、做笔记与复盘
- 行动者：遇到问题希望快速得到“可执行的步骤与止损”

典型场景：

1) 想系统读两论：打开阅读库→选《实践论》/《矛盾论》→目录跳转→完成训练→保存复盘
2) 遇到不确定决策：打开工具箱→选择模型→填写处境→得到动作序列→保存为一次 run
3) 后续扩展：新增一篇 Markdown 文件→自动出现在“按卷/按主题”两种入口中

## 3. 信息架构（IA）

### 3.1 顶层导航

- 仪表盘（/）
- 阅读库（/library）
- 工具箱（/toolkit）
- 训练与复盘（/training）

### 3.2 页面与路由（App Router）

- `/`：Dashboard
  - 今日推荐（双核）
  - 最近复盘（LocalStorage）
  - 快捷入口（工具箱/阅读/训练）

- `/library`：阅读库入口（双入口）
  - Tab A：按卷/篇（Volume 1-4 → 文章列表）
  - Tab B：按主题/标签（tags 聚合）

- `/library/[slug]`：章节阅读页
  - 主体：Markdown 渲染（包含引用块、代码块）
  - 左侧/顶部：目录（由标题自动生成）
  - 右侧：阅读状态（进度、书签、最近阅读）

- `/toolkit`：生存工具箱
  - 选择模型：实践论模型 / 矛盾论模型 / 冲突分级处置
  - 表单：处境输入 + 可选约束（时间/资源/风险）
  - 输出：行动步骤 + 校验指标 + 失败信号与止损 + 下一轮最小动作
  - 支持保存本次运行（run）

- `/training`：训练与复盘
  - 题库：按篇/标签筛选
  - 训练详情：回答输入、保存草稿
  - 复盘模板：填写→自动保存→导出 Markdown

## 4. 内容模型与扩展策略（关键）

### 4.1 内容源（SSOT）

- 内容文件放在：`/content/**/**/*.md`
- 每篇 Markdown 必须有 YAML frontmatter
- V1 默认读取：`/content/maoxuan/*.md`（两论），未来扩展为多目录

### 4.2 Frontmatter 约定（V1 最小集合）

必填字段：

- slug: string
- title: string
- volume: string（"1" - "4" 或空字符串）
- core_level: "S" | "A" | "B"
- tags: string[]
- scenarios: Record<string, "high" | "medium" | "low">

建议字段（后续可加）：

- summary: string
- date: string
- source: string（出处/版本）

### 4.3 内容索引生成（服务端）

在服务端（RSC / route handler）读取文件系统并生成：

- `chapters`: `Array<{ slug, title, volume, tags, core_level, path, excerpt? }>`
- `volumesMap`: `Record<string, Chapter[]>`
- `tagsMap`: `Record<string, Chapter[]>`

扩展性要求：

- 新增一篇 Markdown（符合 frontmatter）→无需写代码即可出现在 `/library` 的两种入口中

## 5. 工具箱（模型调用）设计

### 5.1 输出结构（统一）

工具箱输出统一为：

- 问题重述（把输入改写成可检验命题/矛盾对）
- 胜负指标（1 条）
- 关键不确定性 / 矛盾图谱（视模型）
- 行动步骤（可执行序列）
- 校验（指标/时间窗/对照）
- 失败信号与止损
- 下一轮最小动作

### 5.2 V1 内置模型集合

- 实践论
  - 模型A：调查研究四步法
  - 模型B：小步试验算法
- 矛盾论
  - 模型A：主要矛盾判定算法
  - 模型C：冲突分级处置（可选展示）

实现策略（V1）：

- 先做“结构化模板引导”而不是复杂的 AI 推理
- 允许用户手工填写关键字段，系统负责组织输出与保存
- 后续可接入模型推理（可选）

## 6. 训练与复盘设计

### 6.1 题库数据模型（V1）

- `Question`：`{ id, title, type, tags?, chapterSlug?, prompt, rubric?, sampleAnswer? }`

来源策略：

- V1 先内置少量题（两论各 ≥3）
- 后续允许从 Markdown 里抽取（可扩展）

### 6.2 复盘模板

支持两套模板（与内容一致）：

- 实践论复盘模板（目标/事实/假设/试验/结果/下一轮）
- 矛盾论复盘模板（主次矛盾/主要方面/打击点/阶段/结构变化/修正）

输出与保存：

- 实时保存到 LocalStorage
- 一键导出 Markdown（浏览器下载）

## 7. 本地保存（LocalStorage）方案

### 7.1 Key 规划

- `maoxuan.reading`：最近阅读、书签、进度
- `maoxuan.toolkit.runs`：工具箱运行记录数组
- `maoxuan.training.answers`：题库答题草稿与历史
- `maoxuan.reviews`：复盘模板填写内容与导出版本

### 7.2 数据结构与迁移

- 每个 key 内都包含 `version` 字段，便于未来 schema 迁移
- 未来接入数据库时，保持同一数据结构，新增 sync 层

## 8. 技术架构（基于现有项目）

### 8.1 现有技术栈

- Next.js 14（App Router）
- TypeScript
- TailwindCSS

### 8.2 关键实现点

内容渲染：

- 服务端读取 Markdown 文件
- 使用 Markdown 渲染库（待在实现阶段确认选型与依赖）
- 目录：从 Markdown 标题生成 TOC

页面结构：

- 复用现有 `Navigation/ThemeToggle` 等组件
- 新增 `library/toolkit/training` 对应页面与组件

## 9. 可访问性与质量要求

- 目录可键盘导航
- 颜色对比度符合基本可读性要求
- 表单有明确 label、错误提示
- 不在客户端打印或记录敏感信息

## 10. 测试与验收

V1 验收清单：

- 阅读库：
  - 两篇可读、目录可跳转
  - `/library` 的“按卷/按主题”两入口均可用
  - 新增一篇 md 后自动出现在两入口
- 工具箱：
  - 至少 3 条模型流可跑通并保存 run
  - 输出结构稳定（含止损）
- 训练与复盘：
  - 题库可答、草稿可保存
  - 复盘模板可填写、本地自动保存、可导出 Markdown

## 11. 风险与后续演进

风险：

- Markdown 渲染库选型与样式一致性（需在实现阶段验证）
- 章节增多后目录与标签聚合的性能（V1 可接受，后续可预编译索引）

后续演进（V2+）：

- 全文搜索（预编译索引）
- 云端保存与多端同步
- 更强的标注系统（高亮、批注、分享）
